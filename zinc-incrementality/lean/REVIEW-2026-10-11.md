# Review of the model, 11 October 2026

A read of the framework (`Task`, `Model`, `Soundness`, `Uniqueness`, `Termination`, `Tree`, `NonLocal`, `Classpath`, `Snapshot`) and of the instances built on it (`Hier`, `JavaSpec`, `SplitProof`), with the enumerated phases in view. Findings first, then what to do about them, in priority order.

## What holds up

The core is small and right. `Task` is the free monad over queries with the trace as the dependency record, and T1 (`run_eq_of_trace`) is the one fact everything else rests on: an oracle that agrees on the trace gives the same output. `Compiler` separates the compiler's algorithm (`unit`, `group`), the view of an output (`iface`, `answer`), and the bridge (`keys`, `π`, `covers`); the three `Obligations` are exactly what T2 needs and nothing more; `Policy.Sound` is the weakest condition on Zinc's heuristics that still gives T3a. Uniqueness (T3b) is the result I would show first to someone who thinks "incremental equals clean" is obvious: a per-unit fixed point is not the clean build unless dependencies are acyclic or interfaces are source-determined, which is sbt/zinc#1284 stated as a theorem. Termination separates the policy regimes cleanly. `NonLocal` catches the Merkle trap (Δ over the recompiled set alone is unsound for a non-local hash) and `Classpath`/`Snapshot` catch the refresh trap. `JavaSpec` shows the instance shape works for a real language rule without touching the framework.

## Findings

**1. Four copies of the framework.** `Compiler` (local hash, keys from the trace), `TCompiler` (keys from the output), `GCompiler` (non-local hash, closure keys), `NCompiler` (upstream snapshots) each restate `envOf`, `override`, `round`, `changed`, `invalidated`, `zinc`, `UpToDate`, `Inv`, and each reproves T2 and T3a. `Tree.lean` is `Soundness.lean` with one line changed. Every new instance has to pick one of the four, and a phase that needs two features (keys from the output and an upstream, which Phase 14 will) has nowhere to go. One general structure (non-local `π` with `hashDeps`, `keys` from output and trace, `covers` under interfaces, an `Up` set) with the four as constructors, and T2/T3a proved once, removes the duplication and the choice. The proofs of the general case already exist in `NonLocal` and `Classpath`; the local cases are specialisations.

**2. The harness checks a stronger property than the theorems promise.** T3a gives a per-unit fixed point; the harness compares classfiles with a clean build, which is T3, and T3 needs Uniqueness's hypotheses: acyclic traced dependencies or source-determined interfaces. Scala with inferred result types in a cycle satisfies neither. No phase checks the hypotheses, and no space contains a cycle with inference, so the harness has never seen the case where T3a holds and T3 fails. That case exists (sbt/zinc#1284) and no Zinc rule can fix it without joint compilation. It deserves its own phase: a small space of mutually recursive units with inferred types, the model's two fixed points, and the harness confirming that incremental and clean differ with nothing stale.

**3. Two families are compositionality failures, not coverage failures, and are filed as the wrong thing.** F5 (Scala 3's missed clash) and F4 (scalac's stale mirror under joint compilation) are cases where `group` on a set does something per-unit compilation never does: report an error only both files together produce, or emit a mirror only joint compilation emits. In the framework that is `¬ comp`, the same obligation Phase 14 finds broken for `Mixed`. PLAN.md calls them "beside resolution"; they should be stated as `comp` counterexamples, which also makes clear why no key fixes them.

**4. Precision has no definition in the framework.** The user's constraint (correctness without invalidating the world) is enforced by hand per phase. The framework can define it: the necessary invalidation after a round is the set of units whose traced answers changed (T1's converse direction, as a definition), and a key set's over-invalidation is `invalidated \ necessary`. With that, "coarse key" and "narrowed key" are comparable by a theorem, not a count, and the enumerations give magnitudes for a quantity that is defined.

**5. Files are not in the model.** Zinc recompiles files, records a top-level import on one class of the file (the first in Scala 2, the last in Scala 3), and invalidates per class. F3 and the whole `first`/`Last` factor of `Names.lean` are this mismatch, modelled ad hoc by a Boolean. A `file : CUnit → File` with rounds closed under files and keys charged to a file's representative would make F3 a framework statement and would expose the same gap for any future key that the bridge charges to the wrong class.

**6. The bridge's recorded keys are never checked against the specification.** The harness checks the instance's `resolve` against the compiler (through the constant-pool probe) and the verdict against classfile equality; it never reads what the bridge actually recorded. Zinc's Analysis has the used names and the member-ref/inheritance edges per class. The dump can include the covering keys the model expects for each case, and the harness can read the Analysis after the build and check they are present. That turns `coverage` from an assumption about the bridge into a per-case check, and it is the one thing that would have caught the package-import gap mechanically.

**7. Trust and labelling.** `native_decide` trusts the compiler; the Java and split phases use kernel `decide`, which is better and should be the rule for witnesses. A CI step with `#print axioms` on the core theorems (only `propext`, `Classical.choice`, `Quot.sound`) and a lint that no `theorem` is proved by `native_decide` would hold the line the specification reframe drew.

**8. Organisation.** Phase numbers are chronological and have collided twice tonight; the file list mixes framework, instances, toys and counterexamples. A directory split (`Zinc/Core`, `Zinc/Instances`, `Zinc/Examples`) and a README table by role rather than by phase would help a reader and the sessions. `Pipelining.lean` (three `native_decide` facts) is subsumed by Phase 14's pipelining theorems and should go.

## Recommendations, in order

1. Precision as a definition in `Model.lean` (finding 4) and F4/F5 restated as `comp` failures (finding 3): small, no conflicts, now, in the Phase 10 instance PR.
2. Keys checked against the Analysis in the harness (finding 6): a Zinc-side change to `Conformance` plus a `keys` field in the dump; the next harness item for the develop session.
3. The cyclic-inference phase (finding 2): one small instance, one small space, a harness run that is justified by a predicted divergence.
4. The framework merge (finding 1), after the open instance PRs land, as one PR: define the general structure, prove T2/T3a once, re-express the four as constructors, and port `Hier`, `JavaSpec`, `SplitProof` by changing their instance declarations only.
5. Files as a layer (finding 5), with the merge or right after.
6. CI lints and the directory split (findings 7, 8), any time.
